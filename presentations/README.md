## Как вносить правки

Скрипты-генераторы жили во временной папке сессии и пропали при перезапуске машины 6 ноября 2026 г.
Теперь исходником служат сами PPTX. Правка — прямо в XML:

```bash
mkdir work && cd work && unzip -q ../Drevniy_Egipet.pptx      # распаковать
# править ppt/slides/slideN.xml (текст — в тегах <a:t>)
python3 - <<'PY'
import os, zipfile
src, out = '.', '../Drevniy_Egipet.pptx'
files = [os.path.relpath(os.path.join(b, n), src).replace(os.sep, '/') for b, _, ns in os.walk(src) for n in ns]
first = ['[Content_Types].xml', '_rels/.rels', 'docProps/app.xml', 'docProps/core.xml', 'ppt/presentation.xml']
order = [f for f in first if f in files] + sorted(f for f in files if f not in first)
with zipfile.ZipFile(out, 'w', zipfile.ZIP_DEFLATED) as z:
    for f in order:
        z.write(f, f)
PY
soffice --headless --convert-to pdf ../Drevniy_Egipet.pptx      # PDF
```

- Ответы по щелчку — фигуры с именами `ANS_1…ANS_n` и блок `<p:timing>` в конце слайда; не удалять их без правки анимации.
- В PDF анимаций нет: всё видно сразу.

## Задачи и как их выполнять

Новый агент должен суметь продолжить работу по этой записке, не читая переписку.
Ключей, паролей и токенов проект не использует. Google Диск подключён в claude.ai как коннектор
(инструменты `mcp__Google_Drive__*`), GitHub работает через git-прокси сессии.

### 1. Еженедельный бэкап (регулярная)

- Когда: каждое воскресенье в 23:00 по Москве. Если в какой-то день бэкап ещё не сделан, сделать сразу.
- Запуск: запланированная задача `trig_016GVeKZqKUvgLdjcAcgSVHu` («Еженедельный бэкап ветки на Google Диск»,
  cron `0 20 * * 0` UTC). Она будит эту сессию, и её текст содержит все шаги.
- Шаги:
  1. Взять название сессии через `get_session` (поле `title`), сейчас это «ГЕНРИХ презентации».
  2. `git fetch` и проверить, что ветка `claude/serene-babbage-vkmr7g` совпадает с origin.
  3. Найти в папке `ai_back-ups` (id `1G2uIhHDVjSS2v2xFl3XQl8dC0nTvfxXn`) файлы, имя которых начинается
     с «ГЕНРИХ презентации_», и отправить их в корзину (`trash_file`). Чужие файлы не трогать.
     Сразу после этого очистить их из корзины, если появится такая команда (сейчас её нет, см. раздел «Бэкап»).
  4. `python3 presentations/backup.py "ГЕНРИХ презентации" <папка>` соберёт ZIP и файл .b64 рядом.
  5. `create_file`: parentId — папка выше, title — `drive_title` из вывода скрипта,
     `contentMimeType` application/zip, `disableConversionToGoogleType` true, `base64Content` — содержимое .b64.
     Содержимое брать командой `cat`, не набирать по памяти: 9 ноября так получилась битая строка.
- Проверка: скачать файл обратно (`download_file_content`), сравнить размер, md5 и SHA-256 с локальным ZIP,
  проверить архив `zipfile.testzip()`. В папке должен остаться ровно один файл этой сессии.
- Перед архивом: сверить эту записку с поручениями владельца и дописать пропущенное (подробно — в разделе «Бэкап»).
- Нельзя: брать имя git-ветки вместо названия сессии, удалять файлы других сессий.

### 2. Правки презентаций по просьбе владельца (по запросу)

- Файлы лежат в `presentations/den-vospitatelya/` и `presentations/drevniy-egipet/`, ветка `claude/serene-babbage-vkmr7g`.
- Как править: см. «Как вносить правки» выше (распаковать PPTX, править XML, перепаковать в нужном порядке).
- Проверка PPTX: `python3 /mnt/skills/public/pptx/scripts/office/validate.py <файл.pptx>`.
- PDF: `soffice --headless --convert-to pdf <файл.pptx>`. Если soffice нет: `apt-get install -y libreoffice-impress`.
- Просмотр: отрендерить PDF в картинки (pymupdf ставится через `pip install pymupdf`) и проверить каждый слайд глазами:
  текст не вылезает, фото не искажены, ответы на месте, нет белых слайдов.
- Сдача: всегда два файла, PPTX и PDF, через `SendUserFile`. Потом закоммитить и запушить в рабочую ветку.
- Нельзя: класть файлы проекта вне папки `presentations/`.

## Правила репозитория (от владельца, 06.11.2026)

1. В основной ветке — только общие правила и инструменты. Материалы проектов — только в папке проекта рабочей ветки.
2. На GitHub без согласования с владельцем не делать: коммитов и слияний в основную ветку, пулл-реквестов, новых веток.
3. Общий инструмент, появившийся в проекте, переносится в основную ветку отдельно и только с согласия владельца.

## Бэкап

Каждое воскресенье в 23:00 по Москве: `python3 presentations/backup.py "ГЕНРИХ презентации"` собирает ZIP,
он загружается на Google Диск в папку `ai_back-ups` с именем `ГЕНРИХ презентации_ГГГГ-ММ-ДД.zip`.
Имя — это название сессии в приложении Claude (брать актуальное), **не** имя git-ветки и не придуманное.
Слова владельца 06.11.2026: «Не используй название git-ветки (вида claude/...) и не придумывай своё.»

Порядок (правило владельца 09.11.2026: «сначала удаляешь старую версию - потом создаешь новую.
Если сегодня бэкап еще не сделал - то делай»):
1. **Сначала удалить старую версию:** найти в `ai_back-ups` файлы этой сессии (имя начинается с
   `ГЕНРИХ презентации_`) и отправить их в корзину. Чужие бэкапы (других сессий) не трогать.
   После этого удалить их из корзины окончательно (правило владельца 11.11.2026, его слова: «после удаления файла
   чтобы очищали корзину»). На 12.11.2026 у коннектора Google Диска есть только `trash_file`, команд окончательного
   удаления и очистки корзины нет. Пока так: архив остаётся в корзине (Диск сам стирает её через 30 дней, а файлы
   папки `ai_back-ups` из корзины удаляет скрипт в аккаунте владельца, его готовит сессия «SOHO AI engine MAIN»).
   В отчёте о бэкапе писать: «прежний архив в корзине».
2. **Потом создать новую:** собрать ZIP, загрузить, скачать обратно и сверить SHA-256.
3. Если в день проверки бэкап ещё не сделан — сделать его сразу, не дожидаясь воскресенья.

Перед архивом (правило владельца 11.11.2026, его слова: «создавая бэкап проверили что сохранили все инструкции
новому агенту и дополнили детальным описанием какие задачи и как их выполнять»), каждую неделю начиная с 15.11.2026:
1. Сверить эту записку с правилами и поручениями владельца в сессии. Пропущенное дописать с датой и, где можно, его словами.
2. Обновить раздел «Задачи и как их выполнять»: на каждую текущую и регулярную задачу — что сделать, где файлы и ветка,
   команды и инструменты, расписание, как проверить, что запрещено, где нужно «да» владельца.
   Проверка: новый агент продолжает работу по одной записке, не читая переписку.
3. Пароли, ключи и токены сюда не писать, только где они лежат.
4. Закоммитить и запушить записку в рабочую ветку, потом собирать архив.

Коннектор Google Диска принимает файл только внутри вызова, поэтому в ZIP идут текстовые материалы и опись
всех файлов ветки с контрольными суммами; сами PPTX и PDF лежат в этой ветке на GitHub (ссылки — в описи).
